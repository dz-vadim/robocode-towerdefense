Нова графіка для Tower Defense

Unity PRO · урок 5 «Самостійна робота. Покращення гри» · набір Kenney Tower Defense Kit

Що ми зробимо. Сама гра лишиться такою, як ти її написав: скрипти не змінюються. Замінимо тільки «одяг»: поле, дорогу, вузли, турелі, ворогів, спавн і замок. Знадобиться проєкт після уроку 5 і 1–2 заняття.

1Завантаж набір

Відкрий kenney.nl/assets/tower-defense-kit і натисни Download. Розпакуй архів.

Ліцензія CC0 означає, що моделі можна використовувати в будь-якій грі, навіть платній, і не треба нікого питати. Але подякувати автору у титрах — гарний тон.

2Імпортуй моделі в проєкт

  1. У вікні Project створи теки Assets/Kenney/TowerDefenseKit/Models.
  2. З архіву перетягни у Models усі файли з теки Models/FBX format разом із підтекою Textures (у ній лежить colormap.png).

3Створи один матеріал на всі моделі

Усі моделі Kenney фарбуються однією картинкою-палітрою. Тому матеріал потрібен лише один.

  1. ПКМ у Assets/Kenney/TowerDefenseKit → Create → Material, назви Kenney.
  2. Shader: Universal Render Pipeline/Lit.
  3. У Base Map перетягни Models/Textures/colormap.png. Smoothness постав близько 0.15, щоб моделі не блищали.
Моделі білі або помаранчеві? У Base Map стоїть не та картинка. Потрібна саме colormap.png з теки FBX, а не variation-a.png.

4Вузол = трав'яний тайл

Тайли Kenney мають розмір рівно 1×1, тож проміжки між вузлами більше не потрібні: поле стане суцільним.

  1. Відкрий префаб Node (подвійний клік).
  2. Transform → Scale = 1, 1, 1.
  3. Mesh Filter → Mesh = tile. Mesh Renderer → Material = Kenney.
  4. Box Collider: Center = 0, 0.3, 0, Size = 1, 0.6, 1.
  5. Дочірній BuildPoint: Position Y = 0.2 (верх тайла).
Навіщо колайдер вищий за тайл? Пам'ятаєш Step Height = 0.001 з уроку 1? NavMesh не дасть ворогу «залізти» на високий колайдер, тому вороги ходять тільки дорогою.

5Розстав вузли щільно

Увімкни прив'язку до сітки з кроком 1 (а не 0.5, як на уроці 1) і пересунь вузли так, щоб вони стояли впритул. Там, де раніше була дорога, лиши порожні клітинки.

6Збери дорогу з тайлів

Створи порожній об'єкт Road і перетягуй у нього тайли дороги на порожні клітинки. Тобі знадобляться чотири види:

ТайлДе ставитиКуди «дивиться» без повороту

Як повернути тайл. «Північ» — це вісь +Z (синя стрілка). Rotation Y:

  • 90: північ стає сходом;
  • 180: північ стає півднем;
  • 270: північ стає заходом.

7Plane стає невидимою підлогою

Ворогам потрібна поверхня для NavMesh, але бачити її не обов'язково.

  1. Вибери Plane і зніми галочку з компонента Mesh Renderer (сам Plane не видаляй!).
  2. Position Y = 0.1 (висота дороги). Scale підбери рівно під поле.

8Нові турелі

Відкрий префаб турелі. Заміни тільки моделі, а все інше не чіпай.

  1. Base → заміни модель на башту tower-round-bottom-a (Scale 0.8, 0.6, 0.8).
  2. Усередині Weapon заміни модель гармати на weapon-cannon. Для інших турелей візьми weapon-turret та weapon-ballista.
  3. Підніми Weapon на верх башти (Position Y ≈ 0.36).
Турель не стріляє? Перевір, що Sphere Collider на Weapon досі Is Trigger і Radius не став крихітним після зміни Scale.

9Вороги-НЛО

  1. Відкрий префаб Enemy. Видали в нього компоненти Mesh Filter і Mesh Renderer (сфера зникне).
  2. Перетягни всередину модель enemy-ufo-a як дочірню, Scale ≈ 0.55.
  3. NavMesh Agent: Radius 0.25, Base Offset 0.15 (НЛО трохи висить над дорогою).
  4. Для EnemyFast та EnemyTank візьми enemy-ufo-b і enemy-ufo-c.

10Спавн і замок

На клітинку спавну постав spawn-round. Замок збери з частин башти, як із конструктора: tower-square-bottom-b → tower-square-middle-a → tower-square-top-a → tower-square-roof-b, кожну частину поверх попередньої.

Кубу FinishPoint вимкни Mesh Renderer: його Box Collider (тригер) і скрипт Castle мають лишитися!

11Ліс навколо поля

Обклади поле тайлами tile-tree, tile-tree-double, tile-tree-quad і tile-rock. Повертай їх на 90°, щоб ліс не виглядав однаково. Познач їх Static, як на уроці 8 (Batching Static).

12Перепечи NavMesh

Поле змінилося, тож навігаційну сітку треба зробити заново: Plane → компонент NavMesh Surface → Bake.

13Камера та іконки магазину

  • Main Camera: Position 0, 8.6, -7.4, Rotation X 52. Background — зелений, під колір трави.
  • Іконки: у теці Previews з архіву є картинки гармат. Імпортуй weapon-cannon.png та інші, постав Texture Type = Sprite і вкажи їх у полі Icon своїх TurretInfo.

Тисни Play, будуй турелі й запускай хвилі!

Додаткове завдання: інші набори з Asset Store

На слайді 6 є ще чотири безкоштовні набори. З ними можна зробити рівні в іншому стилі:

  • Forest — Low Poly Toon Battle Arena / Tower Defense Pack
  • Dungeon — Low Poly Toon Battle Arena / Tower Defense Pack
  • Desert — Low Poly Toon Battle Arena / Tower Defense Pack
  • Goblin & Cannon — анімований ворог-гоблін

Як додати: на сторінці набору натисни Add to My Assets (потрібен вхід в Unity ID) → в Unity відкрий Window → Package Management → Package Manager → My Assets → вибери набір → Download → Import.

Рожеві моделі? Ці набори старіші й зроблені під Built-in render pipeline. Більшість матеріалів Unity оновить сама, а решту виправить Edit → Rendering → Materials → Convert All Built-In Materials to Current SRP.
Помилка «Type 'Rotator' already defines a member called 'Update'»? У наборах Forest і Desert є скрипти з однаковими назвами (Rotator, ChestDemo, MaterialMover). Якщо імпортуєш обидва, загорни скрипти одного з наборів у namespace, наприклад namespace AurynSky.Desert { ... }. Файли не видаляй, бо на них посилаються префаби набору.
Для викладача

Еталонний проєкт: ~/Robocode/Courses/Unity/TowerDefense2026, гілка/тег kenney-art (поверх lesson-08). Меню Robocode → Tower Defense → Apply Kenney art автоматично виконує кроки 3–13 над сценою уроку 8 (скрипт Assets/Editor/Robocode/TowerDefenseArt.cs); зручно для порівняння з роботами учнів.

Ігрова логіка не змінюється: префаби перезаписуються за тими самими шляхами, тому TurretInfo та посилання на сцені не ламаються. Перевірено на ПК (кліки через Input System, хвилі, нагорода) і на Android (IL2CPP, ARM64).

Моделі: Kenney Tower Defense Kit 2.1 (CC0, kenney.nl). Скриншоти: Unity 6000.3.22f1, проєкт TowerDefense2026.
